# Стендовый светильник ESP32 по Wi-Fi

После подключения к Wi-Fi плата объявляет сервис `_kontur._tcp.local.`. Локальный мост «Контура» читает манифест с названием «Светильник ESP32» и создаёт карточку с кнопкой питания и ползунком яркости. Плата управляет светодиодом через ШИМ и возвращает состояние после успешной записи на выход.

## Подключение светодиода

Для **ESP32-DevKitC V4 с модулем ESP32-WROOM-32E** подходит вывод с маркировкой `IO23`. Для другой модели проверь её распиновку и укажи свободный выход в `KONTUR_LED_GPIO`. [Распиновка ESP32-DevKitC V4](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32/esp32-devkitc/user_guide.html)

```text
GPIO23 ─── [330 Ω] ─── анод (+) LED катод (−) ─── GND
                        длинная ножка  короткая ножка
```

Отсоедини USB, собери цепь на макетной плате и снова подключи USB. Используй один обычный красный светодиод и последовательный резистор 330 Ω от 0,125 Вт. Катод обычно со стороны плоской грани корпуса. Питание платы поступает по USB, а выход GPIO подаёт на цепь до 3,3 В. Схема рассчитана на один маломощный светодиод.

## Прошивка

1. В Arduino IDE установи пакет плат **esp32 by Espressif Systems** версии **3.3.5** и библиотеку **ArduinoJson 7.x**. [Настройка Arduino-ESP32](https://docs.espressif.com/projects/arduino-esp32/en/latest/installing.html), [библиотека ArduinoJson](https://arduinojson.org/v7/)
2. Скопируй `secrets.example.h` в `secrets.h` рядом со скетчем. Укажи SSID в `kWifiSsid`, пароль в `kWifiPassword` и случайный токен из 32–128 символов `A-Z a-z 0-9 _ -` в `kDeviceToken`. Установи `KONTUR_LED_GPIO` в номер подключённого вывода. Значение `-1` оставляет выход и сетевую часть выключенными. Git игнорирует `secrets.h`.
3. Открой `KonturWifiLight.ino`, выбери модель платы и её COM-порт и загрузи скетч. При старте светодиод погашен.
4. Запусти локальный мост по инструкции в [README проекта](../../README.md). Компьютер и ESP32 должны быть в одной сети с доступным mDNS. В приложении найди **Светильник ESP32** среди устройств Wi-Fi и при запросе введи `kDeviceToken`.

## Проверка

В мониторе последовательного порта на **115200 бод** дождись строк `HTTP address:` и `Announcing … via _kontur._tcp`. Включи светильник в приложении. Светодиод должен зажечься на 50%. Сравни яркость при 20% и 100%, затем выключи питание. Плата напечатает строку `Light state: …` после успешной записи. При потере Wi-Fi она погасит светодиод и сохранит выбранный уровень яркости до перезагрузки. [Arduino-ESP32 LEDC](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/ledc.html)

Для проверки манифеста открой в браузере адрес платы из монитора порта с путём `/kontur/v1/manifest`. Проверь состояние в приложении после добавления прибора и ввода токена. Пример первоначального состояния:

```json
{"power":false,"brightness":50}
```

| Метод и путь | Результат |
| --- | --- |
| `GET /kontur/v1/manifest` | Манифест версии 1 с ID платы, типом `light`, признаком `requiresToken` и возможностями |
| `GET /kontur/v1/state` | Последнее состояние в виде JSON |
| `POST /kontur/v1/command` | Принимает JSON с полями `capability` и `value`. Возвращает обновлённое состояние |

Для чтения состояния и отправки команды нужен заголовок `Authorization: Bearer <токен прибора>`. Для команды также нужен `Content-Type: application/json`. Питание принимает `true` или `false`, яркость принимает целое число от 0 до 100. При перезапуске питание сбрасывается, яркость возвращается к 50%.

Соединение моста с платой использует обычный HTTP. Токен защищает от случайных команд в доверенной тестовой сети. Для реальных приборов потребуется шифрование, аутентификация устройств и проверенная схема управления.
