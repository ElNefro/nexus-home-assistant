# Контур · Kontur

Веб-панель для комнат, климата и приборов умного дома. Интерфейс доступен на русском и английском.

## Запуск

- [Опубликованная панель](https://nexus-home-assistant.onrender.com/) развёртывается как Render Static Site. Ветка `main`, команда сборки `true`, каталог публикации `public`.
- Для локальной проверки раздавай `public` на `localhost` статическим HTTP-сервером. Например, при установленном Python запусти `python -m http.server 8080 --directory public` и открой `http://localhost:8080`.
- Проверки проекта: `node --test`. Установка npm-пакетов не требуется.

После первого открытия онлайн панель можно установить из меню браузера. Настройки и показания сохраняются в браузере. Резервную копию дома можно скачать или восстановить через профиль. При смене браузера или домена перенеси данные с помощью копии.

## Режимы

### Поиск ESP32 в домашней сети

1. Подготовь плату по [инструкции для Wi-Fi-светильника](firmware/KonturWifiLight/README.md). Укажи сеть и код прибора в локальном `secrets.h`.
2. На компьютере в той же сети установи Python 3, выполни `python -m pip install -r requirements.txt` и запусти `python local_server.py`.
3. Открой [локальный «Контур»](http://127.0.0.1:8080), выбери комнату и нажми **Добавить прибор**. Выбери светильник в списке устройств Wi-Fi и введи код из `secrets.h`.
4. Проверь питание и яркость. Название, тип, диапазоны и подписи приходят с платы. Для проверки без нагрузки скетч меняет состояние в памяти ESP32.

Мост ищет сервис `_kontur._tcp.local.`, читает манифест и отправляет команды по HTTP в доверенной домашней сети. Браузер обращается к мосту на том же компьютере. После перезапуска панели для управления потребуется снова найти прибор и ввести его код. Код хранится в оперативной памяти моста и не попадает в резервную копию. Опубликованная панель Render показывает ссылку на локальную версию для обнаружения. Для поиска с телефона понадобится доступный в домашней сети шлюз или мобильный клиент.

[Скетч кормушки](firmware/KonturFeeder/KonturFeeder.ino) с прежним объявлением TXT по-прежнему можно найти, добавить в комнату и увидеть в списке. Карточка управления появится после добавления манифеста и интерфейса команд в эту прошивку.

Поддерживаемые приборы с переключателем питания используют одинаковый режим **«Включать каждые…»**. **«Авто»** опирается на влажность у увлажнителя и чистоту воздуха у очистителя. Для подключённых приборов нужны свежие показания реального датчика из этой комнаты. Режимы выполняются в открытой панели. Старое сохранённое расписание по времени действует до выбора нового режима или отключения.

Для проверки обмена по BLE используй [стендовую прошивку увлажнителя](firmware/README.md).

Предупреждения отображаются на главной. При разрешении браузера подключённая стендовая плата может вызвать уведомление на этом же устройстве, пока панель открыта. Профиль и роль существуют в локальных данных.

## До продуктового запуска

Управление выпущенными устройствами, облачная синхронизация, учётные записи с проверкой ролей и доставка push при закрытой панели требуют серверной части и прошивки для конкретного оборудования. Перед продажей также нужны проверка целевой платы и безопасности подключения, испытания потерянной связи и отключения питания, тесты на целевых телефонах, документация поддержки и проверки по требованиям выбранных рынков. Стендовый BLE-режим предназначен для разработки.
