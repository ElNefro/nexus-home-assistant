# Контур · Kontur

Веб-панель для комнат, климата и приборов умного дома. Интерфейс доступен на русском и английском.

## Запуск

- [Опубликованная панель](https://nexus-home-assistant.onrender.com/) развёртывается как Render Static Site. Ветка `main`, команда сборки `true`, каталог публикации `public`.
- Для локальной проверки раздавай `public` на `localhost` статическим HTTP-сервером. Например, при установленном Python запусти `python -m http.server 8080 --directory public` и открой `http://localhost:8080`.
- Проверки проекта: `node --test`. Установка npm-пакетов не требуется.

После первого открытия онлайн панель можно установить из меню браузера. Настройки и показания сохраняются в браузере. Резервную копию дома можно скачать или восстановить через профиль. При смене браузера или домена перенеси данные с помощью копии.

## Локальный предпросмотр общего дома

Запусти `python -m pip install -r requirements.txt`, затем `python local_server.py`.
Открой [localhost:8080](http://localhost:8080/). Для проверки двух аккаунтов используй
обычное и приватное окна браузера, открытые на одном адресе. `localhost` и
`127.0.0.1` имеют раздельные данные браузера.

1. В **Профиле → Общий дом** создай аккаунт и сохрани одноразовый код восстановления.
2. Создай дом. Отметь **«Перенести мои комнаты и приборы»** или восстанови старую копию в локальном режиме перед созданием дома.
3. Скопируй код приглашения. Во втором окне зарегистрируй другой аккаунт и нажми **«Войти по приглашению»**.
4. После подключения светильника переключи его от имени участника. Обоим пользователям будет доступно подтверждённое сервером состояние. После отзыва доступа сервер отклоняет чтение дома и новые команды участника.
5. Для теста ESP32 с компьютера добавь её в комнату общего дома через Wi-Fi. Код прибора проверяется на ESP32. После перезапуска локального сервера связь с платой нужно восстановить через «Найти в сети».

Панель и API работают на одном адресе. SQLite хранит аккаунты, дома, права и состояние. Отдельная база хранит подписки и события push. Данные предпросмотра пишутся в `.local-work`, путь к базе можно задать через `KONTUR_DB`. Расписания общего дома и обработка пустого бака продолжают работать при закрытой вкладке, пока локальный сервер запущен. Состояние физических приборов подтверждает мост. Локальные правила работают без внешнего интернета при доступной домашней сети. Web Push использует внешнюю инфраструктуру браузера.

В профиле можно настроить push о событиях подключённых приборов. Код восстановления показывается при регистрации и заменяется после восстановления доступа. При отзыве доступа отправка для участника прекращается.

Телефон не может открыть `localhost` компьютера. Проверка телефона и push требует доступного устройству HTTPS-адреса. На iPhone Web Push поддерживается в PWA, добавленной на экран «Домой» на iOS 16.4 и новее. На Android нужен браузер с Push API и разрешение на уведомления. На физических телефонах этот этап ещё не проверен.

Для будущего режима без компьютера PWA потребуется HTTPS-сервер, а плата должна держать исходящее соединение с ним и подтверждать состояние. Это позволит управлять извне без проброса входящих портов. Первичная передача Wi-Fi на новую плату требует отдельного сценария, например локальной страницы настройки, открываемой при подключении телефона к временной сети ESP. Текущий стенд использует заранее заданную сеть.

## Режимы

### Поиск ESP32 в домашней сети

1. Подготовь плату по [инструкции для Wi-Fi-светильника](firmware/KonturWifiLight/README.md). Укажи сеть и код прибора в локальном `secrets.h` для Arduino или `kontur_config.py` для MicroPython.
2. На компьютере в той же сети установи Python 3, выполни `python -m pip install -r requirements.txt` и запусти `python local_server.py`.
3. Открой [локальный «Контур»](http://127.0.0.1:8080), выбери комнату и нажми **Добавить прибор**. Выбери светильник в списке устройств Wi-Fi и введи код из локального файла настроек прошивки.
4. Проверь питание и яркость. Название, тип, диапазоны и подписи приходят с платы. В прошивке можно задать GPIO для обычного светодиода. После подключения светодиод реагирует на команды питания и яркости.

Мост ищет сервис `_kontur._tcp.local.` и отправляет запрос обнаружения «Контура» по UDP на порт `42424`. Оба способа приводят к одному манифесту и одним HTTP-командам в доверенной домашней сети. Браузер обращается к мосту на том же компьютере. После перезапуска панели для управления потребуется снова найти прибор и ввести его код. Код хранится в оперативной памяти моста и не попадает в резервную копию. Опубликованная панель Render показывает ссылку на локальную версию для обнаружения. Для поиска с телефона понадобится доступный в домашней сети шлюз или мобильный клиент.

[Скетч кормушки](firmware/KonturFeeder/KonturFeeder.ino) с прежним объявлением TXT по-прежнему можно найти, добавить в комнату и увидеть в списке. Карточка управления появится после добавления манифеста и интерфейса команд в эту прошивку.

Поддерживаемые приборы с переключателем питания используют одинаковый режим **«Включать каждые…»**. **«Авто»** опирается на влажность у увлажнителя и чистоту воздуха у очистителя. Для подключённых приборов нужны свежие показания реального датчика из этой комнаты. Режимы выполняются в открытой панели. Старое сохранённое расписание по времени действует до выбора нового режима или отключения.

Предупреждения отображаются на главной. При разрешении браузера подключённый прибор может вызвать уведомление на этом же устройстве, пока панель открыта. Профиль и роль существуют в локальных данных.

## До продуктового запуска

Управление выпущенными устройствами, облачная синхронизация, учётные записи с проверкой ролей и доставка push при закрытой панели требуют серверной части и прошивки для конкретного оборудования. Перед продажей также нужны проверка целевой платы и безопасности подключения, испытания потерянной связи и отключения питания, тесты на целевых телефонах, документация поддержки и проверки по требованиям выбранных рынков.
